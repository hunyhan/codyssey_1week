터미널·리눅스

용어뜻예
터미널 (Terminal)글자로 명령을 입력하고 결과를 글자로 보는 창이다. 명령을 실제로 처리하는 것은 그 안에서 실행되는 프로그램이다.
PowerShell (PS)Windows에 들어 있는 터미널 프로그램(셸)이다. 프롬프트 앞의 PS가 PowerShell이라는 표시다.
프롬프트 (Prompt)터미널이 "명령을 입력하세요"라고 보여 주는 앞부분이다. 지금 어느 터미널인지, 누구로, 어느 폴더에 있는지를 알려 준다.
관리자 권한시스템 설정을 바꿀 수 있는 높은 권한이다. Windows에서는 "관리자로 실행"한 PowerShell이 이 권한을 가진다.프롬프트가 C:\Windows\system32에서 시작하면 관리자 PowerShell일 가능성이 높다.
커널 (Kernel)운영체제의 핵심이다. 하드웨어(CPU, 메모리, 디스크)를 직접 다루고 프로그램이 그것을 쓰게 해 준다.
배포판 (Distribution, Distro)리눅스 커널에 기본 프로그램, 설정, 설치 도구를 묶어 바로 쓸 수 있게 만든 운영체제 묶음이다. Ubuntu, Debian, Fedora 등이 있다.
리눅스와 우분투리눅스는 커널(또는 그 계열 전체)이고, 우분투는 리눅스 커널을 쓰는 배포판 중 하나다. 같은 말이 아니다.
LTS (Long Term Support)장기 지원 버전이다. 보안 업데이트를 오랫동안(보통 몇 년) 받을 수 있다. Ubuntu는 짝수 해 4월 버전(예: 24.04, 26.04)이 LTS다.Ubuntu-24.04 = 2024년 4월에 나온 LTS
리눅스 사용자 계정리눅스 안에서 쓰는 사용자 이름과 비밀번호다. Windows 계정과는 별개다.
sudo와 rootroot는 리눅스의 최고 관리자 계정이다. sudo는 일반 사용자가 명령 하나를 관리자 권한으로 실행할 때 앞에 붙이는 말이다. 이때 내 리눅스 비밀번호를 묻는다.사용자 생성 직후 안내 문구 To run a command as administrator (user "root"), use "sudo <command>".
경로(Path)와 루트(/)경로는 파일이나 폴더의 위치를 적는 방법이다. 리눅스에서 가장 위의 폴더를 루트라고 하고 /로 쓴다. 폴더 구분은 /로 한다(Windows는 \).
마운트(mount)와 /mnt다른 저장 공간(디스크, 폴더)을 지금 쓰는 폴더 구조의 한 자리에 연결해 붙이는 것이다. /mnt는 그런 연결을 붙여 두는 자리로 흔히 쓰는 폴더다.
which명령을 쳤을 때 실제로 실행되는 프로그램 파일이 어디에 있는지 보여 주는 명령이다.
그룹(groups)과 permission denied그룹은 권한을 함께 받는 사용자 묶음이다. groups는 지금 터미널의 내가 속한 그룹을 보여 준다. permission denied는 "권한이 없어 거절됨"이라는 오류다.
파일 권한 r/w/x와 chmod리눅스 파일에는 나·그룹·나머지 각각에게 r(읽기)/w(쓰기)/x(실행) 허용 여부가 붙어 있다. chmod(change mode)는 이 허용 표를 바꾸는 명령이고, ls -l로 확인한다.-rw-r--r-- = 나는 읽기·쓰기, 그룹과 나머지는 읽기만
홈 폴더 (~)사용자마다 하나씩 있는 내 폴더다. ~는 그 홈 폴더를 짧게 쓴 표시다.
cd현재 위치(폴더)를 옮기는 명령이다. change directory의 약자.cd ~(홈으로), cd ..(한 칸 위로), cd terminal-practice(아래 폴더로)
pwd지금 있는 폴더의 전체 경로를 보여 주는 명령이다. print working directory의 약자.
ls와 ls -als는 현재 폴더 안의 목록을 보여 준다. -a(= --all)를 붙이면 숨김 파일까지 모두 보여 준다. 목록은 만든 순서가 아니라 이름 순서다.
--help명령 뒤에 붙이면 그 명령의 사용법과 옵션 목록을 보여 준다.ls --help → Usage: ls [OPTION]... [FILE]...
숨김 파일 (dotfile)리눅스에서는 이름이 .으로 시작하는 파일·폴더가 숨김이다. 따로 켜는 "숨김 설정"은 없다. ls에는 안 보이고 ls -a에는 보인다.
. 과 ...은 현재 폴더, ..은 한 칸 위(상위) 폴더를 가리키는 이름표다. 어느 폴더에나 늘 있어서 빈 폴더에서도 ls -a에 나온다.
절대 경로와 상대 경로절대 경로는 /부터 시작해 어디서 써도 같은 곳을 가리킨다. 상대 경로는 지금 위치를 기준으로 정해진다(., .., backup/).
mkdir새 폴더를 만드는 명령이다. make directory의 약자.mkdir terminal-practice, mkdir backup
touch빈 파일을 만드는 명령이다. 이미 있는 파일이면 내용은 그대로 두고 수정 시간만 바꾼다.touch memo.txt → ls에 memo.txt
Tab 자동완성이름 앞부분만 치고 Tab을 누르면 bash가 나머지를 채워 준다. 한 번 = 하나뿐이면 채움, 두 번 = 후보 목록. 폴더면 끝에 /가 붙는다.cd ter + Tab → cd terminal-practice/
cat파일 내용을 화면에 보여 주는 명령이다.cat memo.txt → secend
echo적은 글자를 그대로 화면에 출력하는 명령이다. 혼자서는 파일을 바꾸지 않는다.echo "third" → 화면에 third, cat memo.txt는 그대로
> 와 >> (출력 보내기, 리다이렉션)명령의 출력을 화면 대신 파일로 보낸다. >는 파일을 비운 뒤 새로 쓰고(덮어쓰기), >>는 뒤에 이어 붙인다.
이어쓰기 프롬프트(>)와 Ctrl + C따옴표를 닫지 않는 등 명령이 덜 끝나면, 셸은 줄 앞에 >를 보여 주며 "계속 입력하세요" 상태가 된다. Ctrl + C는 지금 하던 것을 취소하고 프롬프트로 돌아온다.echo "hello: → 줄마다 >, exit도 안 먹힘 → Ctrl + C(^C)로 복귀
cp파일을 복사하는 명령이다. cp 원본 사본 또는 cp 원본 폴더/. 원본은 그대로 남고 별개의 사본이 하나 더 생긴다.
mv파일을 옮기거나 이름을 바꾸는 명령이다. mv 원본 새이름 = 이름 바꾸기, mv 원본 폴더/ = 옮기기. 원래 자리·이름에는 남지 않는다.
rm과 rm -rrm은 파일을 지우는 명령이다. 폴더는 -r(recursive, 안쪽까지 차례로)을 붙여야 안의 내용까지 함께 지운다. 터미널에서 지운 것은 휴지통에 가지 않는다.
Command not found그런 이름의 명령이 없다는 오류다. 실행된 것이 없으니 아무것도 바뀌지 않는다.rma -r backup/ → Command 'rma' not found, but there are 17 similar ones.
ls -l목록을 자세히(long) 보여 준다. 한 줄에 권한 10글자, 주인, 그룹, 크기, 수정 시각, 이름이 나온다.
파일 주인과 그룹 칸ls -l의 3번째 칸은 파일 주인(사용자), 4번째 칸은 파일이 속한 그룹이다. 권한 10글자의 "나" 칸은 이 주인에게, "그룹" 칸은 이 그룹에게 적용된다.
숫자 권한 표기 (644, 755)r=4, w=2, x=1, -=0을 칸(나/그룹/나머지)마다 더해 숫자 3개로 쓰는 방법이다. 0~7은 조합이 하나뿐이라 숫자에서 글자로 되돌릴 수 있다.
Permission denied와 Operation not permitted둘 다 "허락되지 않음" 오류다. Permission denied는 권한 표(rwx) 때문에 막힌 것, Operation not permitted는 그 동작 자체를 할 자격(예: 주인이 아님)이 없어 막힌 것으로 보면 된다.
셸 (Shell)과 bash내가 친 명령을 읽고 실행해 주는 프로그램이다. Ubuntu에서 기본으로 쓰는 셸이 bash다. 터미널(창)과 다르다: 터미널은 화면, 셸은 그 안에서 명령을 받아 주는 프로그램.Ubuntu-24.04 터미널에서도 bash가 돌고 있다. docker run -it ubuntu bash의 마지막 bash = 컨테이너 안에서 실행할 셸.
exit지금 쓰고 있는 셸을 끝내는 명령이다. 컨테이너 안에서 치면 그 bash가 끝난다. 그 bash가 메인 프로그램이었다면 컨테이너는 Exited (0)이 된다.
인자 (argument)명령 뒤에 띄어쓰기로 붙이는 대상이다. 터미널은 띄어쓰기로 명령과 인자를 나눈다.cd ..의 .., explorer.exe .의 ., notepad.exe Dockerfile의 Dockerfile, docker exec -it my-nginx bash의 my-nginx와 bash
curl터미널에서 주소로 요청을 보내고, 돌아온 내용을 글자 그대로 화면에 찍는 명령. 요청한 주소 하나만 받는다(브라우저처럼 style.css를 따로 더 요청하지 않음).curl http://localhost:8081 → <!doctype html>부터 HTML 원본. curl http://localhost:8080/style.css → 404 Not Found HTML. curl http://localhost → Failed to connect to localhost port 80 … Couldn't connect to server
↑ ↓ · Ctrl+R · history지난 명령을 다시 쓰는 방법이다. ↑/↓는 하나씩 불러오고, Ctrl+R은 글자로 검색하고, history는 목록을 보여 준다.Ctrl+R 누르고 show-origin 입력

WSL

용어뜻예
WSL / WSL2 (Windows Subsystem for Linux)Windows 안에서 리눅스를 실행하게 해 주는 기능이다. WSL2는 가벼운 가상머신 안에 진짜 리눅스 커널을 하나 띄우고, 그 위에서 배포판을 실행한다. WSL1은 예전 방식이고 이 컴퓨터에서는 지원되지 않는다.
가상머신 (Virtual Machine, VM)컴퓨터 안에 소프트웨어로 만든 또 하나의 컴퓨터다. 그 안에서 다른 운영체제를 실행할 수 있다.
wsl --statusWSL의 전체 상태(기본 배포판, 기본 WSL 버전)를 보여 주는 명령이다.기본 배포: Ubuntu, 기본 버전: 2
wsl --list --verbose이 컴퓨터에 설치된 배포판 목록을 자세히(verbose) 보여 준다. 열은 *(기본), NAME, STATE, VERSION이다.
STATE (Running / Stopped)배포판이 지금 켜져 있는지(Running), 꺼져 있는지(Stopped)다.
기본 배포판 (*)wsl만 입력했을 때 열리는 배포판이다. 목록에서 * 표시가 붙는다.
wsl --list --online설치할 수 있는 배포판 목록을 보여 준다. 인터넷 연결 상태를 보여 주는 명령이 아니다.
NAME과 FRIENDLY NAME--online 목록에서 한 배포판을 부르는 두 가지 이름이다. NAME은 명령에 쓰는 이름(예: Ubuntu-24.04), FRIENDLY NAME은 사람이 읽기 좋은 설명용 이름(예: Ubuntu 24.04 LTS)이다.
wsl --install배포판을 내려받아 설치하는 명령이다. 뒤에 NAME을 적는다.wsl --install Ubuntu-24.04
프로비저닝 (Provisioning)새로 만든 시스템을 처음 쓸 수 있게 준비하는 과정이다. 설정 파일을 만들고, 사용자를 만드는 일 등이 들어간다.Provisioning the new WSL instance Ubuntu-24.04
wsl -d열 배포판을 골라서 실행하는 옵션이다. -d는 distribution(배포판)의 약자다.wsl -d Ubuntu-24.04
WSL integrationDocker Desktop 설정(Resources → WSL integration)에서 고른 배포판에 Docker 클라이언트를 넣고 데몬과의 연결 통로를 열어 주는 기능이다.켜기 전 which docker → /mnt/c/...(안내용 파일) / 켠 후 → /usr/bin/docker, Docker version 29.8.0
wsl --set-default기본 배포판(wsl만 쳤을 때 열리는 것)을 바꾸는 명령이다.wsl --set-default Ubuntu-24.04 → 목록의 *가 Ubuntu-24.04로 이동
wsl --unregister배포판을 등록 해제해 그 안의 파일까지 모두 지우는 명령이다. 되돌릴 수 없다.wsl --unregister Ubuntu → 남은 배포판 Ubuntu-24.04(*), docker-desktop
explorer.exe .Ubuntu 터미널에서 Windows 탐색기를 부르는 명령. 인자 .(지금 폴더)를 주면 지금 보고 있는 리눅스 폴더가 탐색기로 열린다.
notepad.exe 파일Ubuntu 터미널에서 Windows 메모장으로 파일을 여는 명령. 명령은 notepad.exe, 인자는 열 파일 이름.notepad.exe Dockerfile → 쓰고 Ctrl + S로 저장 → Ubuntu에서 cat Dockerfile로 같은 내용 확인
\\wsl.localhost\ 경로Windows 탐색기에서 Ubuntu 안의 폴더를 여는 주소. /mnt/c(Ubuntu → Windows)의 반대 방향이다.

Docker

용어뜻예
Docker프로그램과 그 실행 환경을 "컨테이너"라는 단위로 묶어서, 어느 컴퓨터에서나 같은 방식으로 실행하게 해 주는 도구다.docker --version → Docker version 29.8.0, build 88096ef
Docker DesktopWindows/macOS에서 Docker를 쓰게 해 주는 앱이다. 앱을 켜면 Docker 데몬이 실행되고, 컨테이너 목록을 화면으로 볼 수 있다.화면 아래 "Engine running" 표시 = 데몬이 동작 중
docker-desktop 배포판Docker Desktop이 스스로 만들어 쓰는 WSL 배포판이다. 사용자가 작업하는 곳이 아니다.
Docker 클라이언트 (CLI)터미널에서 docker라고 입력해 실행하는 프로그램이다. 직접 일을 하지 않고, 데몬에게 요청을 보내고 결과를 받아 보여 준다.
Docker 데몬 (Docker Engine)실제로 이미지를 내려받고 컨테이너를 만들고 실행하는 프로그램이다. 뒤에서 계속 돌면서 클라이언트의 요청을 기다린다.
docker info데몬에 연결해서 상태를 받아 오는 명령이다. 데몬에 연결되지 않으면 에러가 난다. (docker --version은 클라이언트 버전만 보여 주므로 데몬 없이도 나온다.)
컨테이너 (Container)이미지를 실행해서 만든, 격리된 실행 공간이다. 그 안에서 프로그램이 돈다.
이미지 (Image)컨테이너를 만드는 데 쓰는 틀이다. 프로그램과 실행에 필요한 파일이 들어 있다. 이미지가 컴퓨터에 없으면 데몬이 먼저 내려받는다.
docker run hello-worldhello-world 이미지로 컨테이너를 만들어 실행하는 명령이다. Docker가 제대로 동작하는지 확인할 때 많이 쓴다.
Pause와 StopPause는 컨테이너를 일시 정지(그대로 멈춰 둠)하는 것이고, Stop은 컨테이너를 종료하는 것이다.
소켓 (docker.sock)같은 컴퓨터 안의 프로그램끼리 대화하는 연결 통로다. Docker 클라이언트는 /var/run/docker.sock을 통해 데몬에게 요청을 보낸다.permission denied while trying to connect to the docker API at unix:///var/run/docker.sock
docker images데몬이 갖고 있는 이미지(틀) 목록을 보여 준다.
docker ps와 docker ps -adocker ps는 동작 중인 컨테이너 목록, -a(all)를 붙이면 꺼진 것까지 전부. 제목 칸은 같고 줄(컨테이너 수)이 늘어난다.docker ps 5개(모두 Up), docker ps -a 7개(+ Exited (0) 2개)
STATUS (Up / Exited)docker ps 목록의 상태 칸. Up … = 켜져 있음(켜진 지 얼마나), Exited (숫자) … = 꺼짐(언제 꺼졌는지). 괄호 숫자는 종료 코드로 0이면 정상 종료.Up About a minute (healthy), Exited (0) 6 weeks ago
docker logs (--tail)컨테이너가 돌면서 화면에 출력한 기록을 보여 준다. 꺼진 컨테이너도 지우기(docker rm) 전까지는 기록이 남아 있다. --tail 20은 마지막 20줄만.
docker stats동작 중인 컨테이너들이 지금 쓰는 CPU·메모리·네트워크를 실시간으로 보여 준다. 저절로 끝나지 않아 Ctrl+C로 멈춘다.
Docker Hub와 PullDocker Hub는 인터넷에 있는 이미지 저장소다. Pull은 거기서 이미지를 내려받는 것. docker run을 했는데 이미지가 없으면 데몬이 알아서 Pull부터 한다.Unable to find image 'hello-world:latest' locally → latest: Pulling from library/hello-world → Status: Downloaded newer image for hello-world:latest
태그 (:latest)이미지 이름 뒤 : 다음에 붙는 버전 이름표. 따로 적지 않으면 latest(최신판)가 붙는다.
컨테이너 이름 (NAMES)docker ps -a의 NAMES 칸. docker run에서 이름을 따로 주지 않으면 Docker가 "형용사_유명인" 꼴로 아무렇게나 지어 준다. 이름에는 역할 정보가 없다.
컨테이너 ID (CONTAINER ID)컨테이너마다 붙는 고유 번호. docker ps에는 앞 12자리가 나온다. 컨테이너 안에 들어가면 프롬프트 root@ 뒤에도 같은 값이 보인다.
COMMAND (메인 프로그램)docker ps의 COMMAND 칸. 그 컨테이너가 시작될 때 실행한 프로그램 하나(메인 프로그램)다. 컨테이너는 이 프로그램이 도는 동안만 Up이고, 끝나면 Exited가 된다.
CREATEDdocker ps의 CREATED 칸. 그 컨테이너가 만들어진 때다. 켜진 뒤 지난 시간은 STATUS의 Up ○○가 따로 보여 준다. docker ps -a는 CREATED가 최신인 것을 맨 위에 둔다.
docker stop과 docker startdocker stop 이름 = 실행 중인 컨테이너의 메인 프로그램에 끝내라는 신호를 보내 멈춘다(Exited). 삭제가 아니라 ps -a에 그대로 남는다. docker start 이름 = 멈춘 컨테이너를 그 설정 그대로 다시 켠다. 이름 여러 개를 띄어 써서 한 번에 할 수 있다.
docker run -it (컨테이너 안에 들어가기)-i(interactive) = 키보드 입력을 컨테이너 안 프로그램에 계속 전달, -t(tty) = 터미널 화면을 붙여 준다. 둘을 함께 써야 컨테이너 안에 "들어가서" 명령을 칠 수 있다.
docker start -ai와 docker attachdocker start -ai ID = 멈춘 컨테이너를 다시 켜고 메인(COMMAND) 프로그램에 화면(-a, attach)과 입력(-i)을 연결한다. docker attach ID = 이미 돌고 있는 컨테이너의 메인 프로그램에 내 창을 연결한다. 둘 다 새 프로그램을 띄우지 않는다.
docker exec이미 돌고 있는 컨테이너 안에서 새 프로그램을 하나 더 실행한다. -it와 bash를 주면 셸을 하나 더 띄워 들어간다. 여기서 exit해도 메인 프로그램은 그대로라 컨테이너는 Up.
커스텀 이미지 · 베이스 이미지커스텀 이미지 = 남이 만든 이미지를 바탕으로 내가 필요한 것을 더해 새로 만든 이미지. 베이스 이미지 = 그 출발점(Dockerfile의 FROM). 베이스 이미지 자체는 바뀌지 않는다.FROM nginx + 내 학습기록 HTML → my-nginx:v2. docker images에 nginx:latest와 my-nginx:v2가 다른 줄, 다른 ID로 따로 있다.
Dockerfile (FROM, COPY, #, CMD)이미지를 만드는 순서를 적은 글자 파일. 이름은 대문자 D로 시작하고 확장자가 없다. FROM 이미지:태그(첫 줄, 출발점), COPY 보낼파일 이미지안의경로(빌드 폴더의 파일을 이미지 안에 넣기), #(주석, Docker가 읽지 않음), CMD(시작할 때 실행할 프로그램, 안 쓰면 베이스의 것을 물려받음).FROM nginx / COPY site/ /usr/share/nginx/html. CMD를 안 써서 COMMAND는 베이스의 "/docker-entrypoint.…"
docker build -t 이름:태그 .Dockerfile을 읽어 이미지를 만드는 명령. -t 이름:태그 = 만들어질 이미지에 붙일 이름표. 맨 끝 . = 빌드에 쓸 폴더(지금 위치). 진행 중에 [1/2] FROM …, [2/2] COPY …처럼 단계를 보여 준다.docker build -t my-nginx:v1 . → naming to docker.io/library/my-nginx:v1 → docker images에 my-nginx:v1
빌드 컨텍스트 (빌드 폴더)docker build 맨 끝 .이 가리키는 폴더. Docker는 이 폴더 안의 파일만 넘겨받고, COPY의 앞 경로는 이 폴더에서 출발한다.~/my-nginx에서 docker build -t my-nginx:v1 . → COPY index.html …(그 자리에서 cat index.html이라고 칠 때의 이름). 화면의 transferring context: 3.78kB가 넘어간 양이다(실패 땐 2B).
CACHED (빌드 캐시)빌드할 때 전에 만든 단계의 결과를 그대로 다시 쓴다는 표시. 단계(줄) 하나 단위로 판단한다. 그 줄의 글자와 그 줄이 가져다 쓰는 파일이 둘 다 그대로일 때만 붙고, 하나라도 바뀌면 그 단계를 처음부터 다시 한다.v1 → v2(COPY 줄이 바뀜): CACHED [1/2] FROM …, [2/2] COPY site/ …는 새로 함. 주석만 고친 재빌드: CACHED [2/2] COPY site/ …. site/index.html을 고치면 COPY에 CACHED가 붙지 않는다(예상만, 실행은 안 함).
docker run -d컨테이너를 뒤에서(백그라운드로) 실행하고 터미널을 바로 돌려준다. 출력 대신 긴 컨테이너 ID 한 줄만 나온다. -it(안에 들어가기)와 반대 느낌.docker run -d --name my-nginx nginx → 4f3339587535… 한 줄. 앞 12자리 = docker ps의 CONTAINER ID
--name 이름docker run에서 컨테이너 이름을 정한다. 안 주면 Docker가 아무렇게나 붙인다. 같은 이름은 두 번 쓸 수 없다.--name my-nginx-v2 (이미지 이름 my-nginx:v2와는 다른 것)
-p 8080:80 (포트 연결)docker run에서 내 PC의 8080번 포트로 들어온 요청을 컨테이너의 80번 포트로 보내는 옵션. 준 컨테이너에만 docker ps PORTS 칸에 0.0.0.0:8080->80/tcp처럼 ->가 생긴다.-p 8080:80 → localhost:8080, -p 8081:80 → localhost:8081 (8080은 v1이 쓰고 있어서)
NGINX (엔진엑스)현업에서 가장 많이 쓰는 웹 서버 중 하나. Docker Hub에 nginx 이미지가 있다. 요청을 계속 기다리므로 컨테이너가 계속 Up이다.COMMAND "/docker-entrypoint.…"(NGINX를 준비하고 실행하는 시작 스크립트), 기본 페이지 Welcome to nginx!, 404 화면 아래 nginx/1.31.8(받은 버전)
default.conf (listen, location, root, index)NGINX 기본 설정 파일 /etc/nginx/conf.d/default.conf(/etc = 설정 파일 폴더). listen 80; = 80번 포트에서 기다림. location / { … } = /로 오는 요청에 적용할 규칙. root 폴더; = 보낼 파일을 찾는 폴더. index 파일이름; = 파일 이름 없이 /로 오면 먼저 보낼 파일.root /usr/share/nginx/html; + index index.html index.htm; → 내 페이지는 /usr/share/nginx/html/index.html에 넣는다(원래 Welcome to nginx!는 내 이미지 안에서 덮어써짐).
port is already allocated (호스트 포트 충돌)이미 다른 컨테이너가 잡아 둔 호스트 포트로 -p를 주면 나는 에러. allocated = 이미 누가 쓰기로 잡아 두었다. 컨테이너는 만들어지지만(Created) 실행 단계에서 묶기(Bind)에 실패한다.docker run -d --name my-nginx-test -p 8080:80 nginx → 컨테이너 ID 한 줄 → Bind for 0.0.0.0:8080 failed: port is already allocated → docker ps -a에 STATUS Created
docker rm컨테이너를 삭제한다. docker ps -a에서도 사라진다. 돌고 있는(Up) 컨테이너는 거절하고, 멈춘 것(Exited, Created)만 지운다. 휴지통이 없다.docker rm my-nginx-test → my-nginx-test 한 줄 출력. nginx:latest 이미지는 그대로 남는다.
바인드 마운트 (-v 호스트경로:컨테이너경로)docker run에서 호스트(내 PC)의 폴더를 컨테이너 안의 경로에 연결하는 것. 복사가 아니라 연결이라, 호스트에서 저장하면 컨테이너도 같은 파일을 바로 본다. 순서는 -p처럼 호스트:컨테이너, 호스트 경로는 /로 시작하는 절대 경로.
볼륨 (docker volume create · ls · rm, -v 볼륨이름:경로)Docker가 직접 만들고 관리하는 저장 공간. 내 PC 폴더를 지정하지 않고 이름으로 부르며, 위치는 Docker가 정한다(데몬 쪽 docker-desktop 안). docker volume create 이름(만들기), docker volume ls(목록), docker volume rm 이름(지우기, 쓰는 컨테이너를 먼저 지움). docker run에서는 바인드 마운트와 같은 -v로 연결한다: -v 볼륨이름:컨테이너경로.docker volume create mydata → docker run -it --name vol-test1 -v mydata:/data ubuntu bash → /data/memo.txt 저장 → docker rm vol-test1 → vol-test2에 같은 볼륨 연결 → cat /data/memo.txt → in volume (연결 없는 /memo.txt는 사라짐)

Git·GitHub

용어뜻예
Git파일의 변경 이력을 기록하고 관리하는 버전 관리 도구다.git --version → git version 2.54.0.windows.1 (.windows가 붙은 것은 Windows용이라는 표시)
저장소 (Repository, Repo)Git이 관리하는 프로젝트 폴더와 그 변경 이력 전체다. 내 컴퓨터에 있으면 로컬 저장소, GitHub에 있으면 원격 저장소라고 한다.
GitHubGit 저장소를 인터넷에 올려 두고 함께 작업할 수 있게 해 주는 서비스다.
push내 컴퓨터(로컬 저장소)의 커밋을 원격 저장소(GitHub 등)로 올리는 Git 명령이다.
git configGit의 설정(사용자 이름, 이메일 등)을 보고 바꾸는 명령이다.
--globalgit config에 붙여서 "이 사용자 계정 전체에 적용되는 설정"으로 저장하라는 옵션이다.git config --global init.defaultBranch main
user.name · user.email커밋을 만들 때 "누가 만들었나"로 기록되는 이름과 이메일 설정이다.
init.defaultBranch (기본 브랜치)새 저장소를 만들 때 처음 생기는 브랜치 이름을 정하는 설정이다.git config --global init.defaultBranch main
git config --list지금 적용되는 Git 설정을 이름=값 줄로 모두 보여 주는 명령이다.
설정 단계 (system / global / local)Git 설정이 저장되는 세 곳이다. system = 컴퓨터 전체(Git 설치 때 설치 프로그램이 넣음), global = 내 계정 전체(--global), local = 저장소 하나(--global 없이).Git Bash --list에 init.defaultbranch=master(system)와 init.defaultbranch=main(global)이 함께 나옴.
git config 항목이름 (실제 값 하나 보기)--list 없이 항목 이름만 주면, 겹친 설정을 다 따진 뒤 실제로 쓰이는 값 하나만 보여 준다.git config user.email, git config init.defaultBranch
git config --show-origin --get-all 항목이름그 항목이 적힌 줄을 모두 보여 주고, 줄마다 어느 설정 파일에서 왔는지(파일 경로)를 앞에 붙인다. --list에서 같은 항목이 두 번 나올 때 출처를 확인하는 데 쓴다.git config --show-origin --get-all init.defaultBranch
Git Bash (MINGW64)Windows용 Git과 함께 설치되는 터미널이다. Windows에서 ls, cat 같은 리눅스식 명령을 쓸 수 있다.
SSH (Secure Shell)다른 컴퓨터(서버)와 암호화해서 안전하게 연결하는 방법이다. GitHub에 비밀번호 대신 키로 접속할 때 쓴다.
SSH 키 (공개키 · 비밀키)한 쌍으로 만들어지는 두 파일이다. 공개키(.pub)는 GitHub 같은 상대에게 등록하고, 비밀키(.pub 없는 파일)는 내 컴퓨터에만 둔다.id_ed25519(비밀키), id_ed25519.pub(공개키). GitHub Settings → SSH keys에 공개키를 등록.
ssh-keygenSSH 키 한 쌍을 만드는 명령이다. -t는 키 종류, -C는 키에 붙이는 메모(주석)다.ssh-keygen -t ed25519 -C "(이메일)"
passphrase비밀키 파일 자체에 거는 비밀번호다. 비워 두면(Enter) 없이 만들어진다.
키 지문 (fingerprint) · randomart키를 짧게 요약한 값(SHA256:…)과, 그 값을 그림으로 그린 것이다. 키가 같은지 눈으로 비교할 때 쓴다.
~/.ssh 폴더내 홈 폴더 안의 숨김 폴더로, SSH 키가 저장되는 기본 위치다.
로컬 · 원격 (remote)내 컴퓨터 쪽 저장소를 로컬, 서버(GitHub)에 있는 쪽을 원격이라고 부른다.
git clone원격 저장소를 파일과 변경 기록까지 통째로 내 컴퓨터에 복제하는 명령이다. 저장소 이름의 폴더가 생기고, 원격과의 연결도 함께 설정된다.
.git 폴더저장소의 변경 기록과 설정이 들어 있는 숨김 폴더다. 이 폴더가 있어야 Git이 그 폴더를 저장소로 본다.ls -a → ./ ../ .git/ README.md
not a git repository지금 폴더(와 그 위 폴더들)에 .git이 없어서 Git이 저장소로 보지 않는다는 에러다.홈에서 git remote -v → fatal: not a git repository (or any of the parent directories): .git
git remote -v · origingit remote -v는 이 저장소가 연결된 원격 주소를 보여 준다. origin은 clone할 때 원격 주소에 자동으로 붙는 기본 이름이다. fetch는 받아 올 때, push는 올릴 때 쓰는 주소다.
커밋 (commit)파일 변경을 기록한 저장 지점 하나다.저장소 페이지의 Initial commit, 1 Commit
브랜치 (branch) · origin/main브랜치는 커밋들이 이어지는 작업 줄기의 이름이다. main은 기본 브랜치, origin/main은 GitHub의 main이 어디까지 왔는지 내 컴퓨터가 기억해 둔 위치다. Git Bash 프롬프트의 (main)은 지금 작업 중인 브랜치다.~/codyssey_1week (main), VSCode 왼쪽 아래 main
Public · PrivatePublic은 누구나 볼 수 있는 저장소, Private은 나와 내가 허락한 사람만 볼 수 있는 저장소다.저장소 이름 옆 Public
Code 버튼 (HTTPS / SSH 주소)저장소 페이지의 초록색 버튼이다. 누르면 clone에 쓸 주소가 나오고, 접속 방식에 따라 주소가 다르다.
ssh 명령 · git@github.comssh 사용자@서버는 그 서버에 그 사용자로 접속하는 명령이다. git@github.com은 GitHub 서버의 git 사용자로 접속한다는 뜻이고, 내 계정은 키를 보고 찾는다. -T는 명령을 치는 화면을 열지 않는 옵션이다.
호스트 확인 질문 · 호스트 키 지문처음 접속하는 서버면 SSH가 진짜 서버가 맞는지 묻는다. 화면의 지문을 공식 문서 값과 비교한 뒤 yes를 입력한다.Are you sure you want to continue connecting (yes/no/[fingerprint])?
known_hostsyes로 답한 서버를 적어 두는 파일(~/.ssh/known_hosts)이다. 여기 적힌 서버는 다음부터 묻지 않는다. 환경마다 따로 있다.Warning: Permanently added 'github.com' (ED25519) to the list of known hosts.
VSCode (code --version · code .)코드를 쓰는 편집기다. Windows 프로그램이다. code --version은 버전, code .은 지금 폴더를 VSCode로 여는 명령이다.code --version → 1.145.0
권한 승인 (OAuth)내 GitHub 비밀번호를 VSCode에 알려 주는 대신, GitHub 화면에서 VSCode가 내 계정을 써도 된다고 허락하는 방식이다.
제한 모드 (Restricted Mode)VSCode가 아직 신뢰하지 않은 폴더를 여는 방식이다. Git 같은 일부 기능을 꺼 둔다. 왼쪽 아래 표시를 눌러 내가 믿는 폴더라고 정하면(작업 영역 신뢰) 풀린다.왼쪽 아래 제한 모드 → 신뢰 → main
소스 제어 · 그래프VSCode의 Git 화면이다. 왼쪽 가지 모양 아이콘으로 열고, 그래프에는 커밋 목록과 어떤 브랜치가 어느 커밋에 있는지 나온다.
git status지금 무엇이 바뀌었는지 보여 준다. 아무것도 바꾸지 않아서 자주 실행해도 된다. 다음에 쓸 명령도 안내한다.modified: README.md
git add · stagedgit add는 수정한 파일 중 다음 커밋에 넣을 파일을 고르는 명령이다. 골라 둔 상태를 staged라고 한다.Changes not staged for commit(빨강) → git add README.md → Changes to be committed(초록)
git commit -mgit add로 고른 파일로 커밋을 만든다. -m 뒤에 무엇을 바꿨는지 메시지를 적는다.
커밋 ID (해시)커밋마다 붙는 고유한 값이다. 화면에는 보통 앞부분만 줄여서 나온다.
git log커밋 기록을 보여 주는 명령이다. -1은 최근 1개, --format은 표시 형식이다.git log -1 --format="%an <%ae>" → 작성자 이름과 이메일
ahead · up to date · working tree cleanahead of 'origin/main' by 1 commit은 내 main이 origin/main보다 1커밋 앞섰다는 뜻이다. up to date는 둘이 같다는 뜻이다. working tree clean은 커밋하지 않은 수정이 없다는 뜻이다.VSCode 왼쪽 아래 0↓ 1↑ = 받을 커밋 0개, 올릴 커밋 1개
pull원격의 새 커밋을 내 컴퓨터로 받아 오는 동작이다.
noreply 이메일GitHub가 계정마다 만들어 주는 공개용 이메일 주소다. 커밋에 진짜 이메일 대신 쓰면 주소가 공개되지 않고, 커밋은 내 계정에 연결된다.

개발 일반

용어뜻예
버전 확인 (--version)프로그램이 설치되어 있는지, 몇 버전인지 확인하는 옵션이다. 대부분의 명령줄 도구가 지원한다.docker --version, git --version
클라이언트와 서버 (Client / Server)클라이언트는 요청하는 쪽, 서버는 요청을 받아 처리하고 결과를 돌려주는 쪽이다.브라우저(클라이언트) ↔ 웹 서버, Docker 클라이언트 ↔ Docker 데몬
CLI (Command Line Interface)글자 명령으로 프로그램을 다루는 방식이다. 마우스로 버튼을 누르는 방식은 GUI(Graphical User Interface)라고 한다.docker 명령 = Docker CLI, Docker Desktop 화면 = GUI
데몬 (Daemon)화면 없이 뒤에서 계속 돌면서 요청이나 일을 기다리는 프로그램이다. 리눅스에서는 이름 끝에 d가 붙는 경우가 많다(예: dockerd).
트러블슈팅 (Troubleshooting)문제가 생겼을 때 원인을 찾고 해결하는 과정이다. 형식은 문제 → 가설 → 확인 → 해결이다.
웹 서버 · 정적 콘텐츠웹 서버 = 브라우저가 "이 페이지 주세요"라고 요청하면 파일을 보내 주는 프로그램(예: NGINX). 정적 콘텐츠 = 요청마다 새로 계산하지 않고 파일 그대로 보내는 내용(HTML, CSS, 그림).학습기록 HTML 폴더 = 정적 콘텐츠. HTML을 http://…로 보여 주려면 웹 서버가 필요하다(ubuntu/alpine에는 기본으로 없음).
localhost"지금 이 주소창을 쓰고 있는 컴퓨터 자신"을 가리키는 주소.http://localhost:8080 = 내 PC. 평가자가 같은 링크를 누르면 평가자 자기 컴퓨터에 접속하므로 내 페이지는 안 보인다.
HTML href (링크·상대 경로)HTML에서 다른 파일을 가리키는 주소다. 브라우저는 index.html을 받은 뒤 style.css 같은 파일을 따로 요청한다.<link rel="stylesheet" href="style.css">
404 Not Found웹 서버가 "요청한 파일이 없다"고 답하는 코드. 서버는 동작 중이고, 그 파일만 없다는 뜻.localhost:8080/용어집.html → 404 Not Found, 아래 nginx/1.31.8
ERR_CONNECTION_REFUSED브라우저가 그 주소(포트)에 연결하려 했는데 기다리는 프로그램이 아무것도 없을 때 나오는 에러. 404(서버는 있는데 파일이 없음)와 다르다.v2 컨테이너를 docker run하기 전에 localhost:8081 접속 → ERR_CONNECTION_REFUSED → run 뒤 정상
"내 컴퓨터에서는 되는데요?"내 환경에서는 되는데 다른 사람 환경에서는 안 되는 문제를 가리키는 현업 표현. 프로그램 버전이나 설정이 서로 달라서 생긴다.상대방이 다른 버전의 DB를 받고 "안 된다"고 하는 경우. 이미지는 프로그램·버전·설정을 함께 담아 이 문제를 줄인다.
포트 (port)한 컴퓨터 안에서 어느 프로그램에게 온 요청인지 가르는 번호(0~65535). 프로그램은 자기 번호를 정해 두고 그 번호로 오는 요청을 기다린다. 주소 뒤 :숫자가 포트이고, 안 쓰면 http는 80번.
호스트 (host)컨테이너를 돌리고 있는 바깥 컴퓨터. 지금은 내 PC.-p 8080:80의 8080 = 호스트(내 PC) 포트, 80 = 컨테이너 포트
IP 주소 (IPv4 / IPv6)네트워크에서 어느 컴퓨터인지 가리키는 주소. 포트가 "컴퓨터 안의 어느 프로그램"이라면 IP는 "어느 컴퓨터". IP:포트로 붙여 쓴다. 적는 방식이 두 가지다: IPv4(127.0.0.1처럼 점 4칸), IPv6(::처럼 콜론).0.0.0.0:8080, 127.0.0.1:55322, [::]:8080(IPv6 주소 뒤에 :포트를 붙일 때 [ ]로 감쌈)
127.0.0.1 / 0.0.0.0 / [::] (PORTS 칸 화살표 앞)PORTS 칸 화살표 앞은 누가 들어올 수 있는지를 보여 준다. 127.0.0.1 = localhost를 숫자로 쓴 것 → 내 PC 안에서만. 0.0.0.0 = 가리지 않고 다 받기 → 내 PC + 다른 컴퓨터. [::] = 0.0.0.0과 같은 뜻의 IPv6 표기. 화살표가 없으면(80/tcp) 아무도.
작업본과 배포본계속 고치는 원본(작업본)과, 다른 사람에게 보여 줄 것만 골라 둔 사본(배포본)을 나눠 두는 방식.
영속성 (persistence)컨테이너(프로그램)가 지워지거나 다시 만들어져도 데이터가 계속 남는 성질.볼륨이나 바인드 마운트에 저장한 파일은 컨테이너를 지워도 남는다. 컨테이너 자기 공간에 만든 파일은 함께 사라진다.
종료 코드 (Exited (0) / Exited (1))프로그램이 끝날 때 남기는 숫자. 0 = 정상, 0이 아니면 마지막에 무언가 실패했다는 뜻. docker ps -a STATUS의 Exited (숫자)가 메인 프로그램의 종료 코드다.vol-test2: 마지막 명령 cat /memo.txt가 실패(No such file)한 채 exit → Exited (1). hello-world와 정상 종료한 bash는 Exited (0).
빌드 (build)소스로 실행할 결과물을 만드는 작업이다. docker build는 이미지를, 펌웨어 빌드는 .hex를 만든다. 커밋과는 별개다.main.c 빌드 → .hex → MCU에 다운로드
