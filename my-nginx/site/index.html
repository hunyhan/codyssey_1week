권한

ls -l의 맨 앞 칸은 종류 1글자와 권한 9글자다. 권한은 3글자씩 주인, 그룹, 기타 사용자 순서로 읽는다.

-rw-r--r--   파일, 주인 rw-, 그룹 r--, 기타 r--  = 644
drwxr-xr-x   폴더, 주인 rwx, 그룹 r-x, 기타 r-x  = 755
글자숫자파일에서폴더에서
r4읽기목록 보기
w2쓰기안에서 만들기, 지우기
x1실행들어가기 (cd)

숫자는 묶음마다 더한다. rwx = 7, rw- = 6, r-x = 5, r-- = 4.

chmod 644 a.txt     # 숫자로 한 번에 지정
chmod g+w a.txt     # 그룹에 쓰기 추가 (664)
chmod u-x test      # 주인의 들어가기 권한 빼기
심화: 권한 에러 읽기
화면원인
permission denied ... docker.sockdocker.sock은 root docker 소유이고 그룹까지만 쓸 수 있다. groups에 docker가 없는 창에서 난다. 다시 접속하면 반영된다
chmod의 Operation not permittedchmod는 파일 주인이나 관리자만 할 수 있다. /mnt/d 파일은 주인이 root로 보여 거절된다

커스텀 이미지

구분뜻
이미지읽기 전용 틀. 환경과 파일이 들어 있다
컨테이너이미지로 실행한 것 하나. 이미지 하나로 여러 개 만들 수 있다
Dockerfile이미지를 만드는 순서를 적은 파일
# 이 저장소의 Dockerfile
FROM nginx
COPY site/ /usr/share/nginx/html
줄뜻
FROM베이스 이미지를 고른다. 실행 명령도 그대로 물려받는다
COPY빌드 폴더의 파일을 이미지 안으로 복사한다
cd my-nginx
docker build -t my-nginx:v3 .                         # 이미지 만들기
docker run -d --name my-nginx-v3 -p 8083:80 my-nginx:v3  # 컨테이너 실행
curl localhost:8083                                   # 응답 확인

site/를 고치면 이미지 안의 파일은 그대로다. 다시 docker build해야 반영된다.

심화: 빌드할 때 알아 둘 것
  • docker build 끝의 .은 지금 폴더를 빌드 폴더로 Docker에 넘긴다는 뜻이다. COPY의 앞 경로는 이 폴더 안에서 찾는다.
  • my-nginx 폴더에서 빌드할 때 cat site/index.html로 열리는 파일은 COPY site/index.html ...로 쓸 수 있다.
  • /home/...이나 /mnt/d/...처럼 빌드 폴더 밖의 파일은 가져올 수 없다. /로 시작해도 빌드 폴더 안에서 찾으므로 not found가 난다.
  • COPY의 뒤 경로는 이미지 안의 위치다.
  • CACHED는 줄과 쓰는 파일이 그대로라서 이전 결과를 다시 썼다는 뜻이다.
  • NGINX는 /etc/nginx/conf.d/default.conf의 root 폴더에서 index 파일을 찾아 보낸다. 그래서 /usr/share/nginx/html에 index.html을 넣는다.
  • 페이지가 가리키는 CSS, 이미지까지 함께 넣어야 한다. 빠지면 꾸밈이 없는 페이지나 404가 나온다.

포트 매핑

컨테이너는 격리되어 있어서 포트를 연결해야 내 컴퓨터에서 접속할 수 있다.

-p 8081:80
   호스트:컨테이너
   브라우저에서 localhost:8081로 들어오면 컨테이너의 80번으로 보낸다
docker ps의 PORTS뜻
0.0.0.0:8081->80/tcp연결됨. 내 컴퓨터의 8081번으로 들어온다
80/tcp화살표가 없다. 내 컴퓨터에서 들어갈 수 없다
심화: 접속이 안 될 때
화면뜻
port is already allocated호스트 포트가 이미 쓰이는 중이다. 컨테이너 포트는 각자 80이어도 되지만 호스트 포트는 겹칠 수 없다
ERR_CONNECTION_REFUSED그 포트에서 기다리는 프로그램이 없다
404 Not Found서버는 답했지만 그 파일이 없다
PORTS 앞 주소들어올 수 있는 곳
127.0.0.1내 컴퓨터 안에서만
0.0.0.0내 컴퓨터의 모든 주소로. 외부 공개에 주의한다

바인드 마운트

내 컴퓨터의 폴더를 컨테이너 안의 경로에 그대로 연결한다. 파일을 고치면 빌드 없이 새로고침만으로 반영된다.

docker run -d --name my-nginx-bind -p 8082:80 \
  -v /home/사용자/my-nginx/site:/usr/share/nginx/html nginx
-v 호스트경로:컨테이너경로
   호스트경로는 / 로 시작하는 절대 경로로 쓴다
이미지에 COPY바인드 마운트
파일 위치이미지 안에 복사본내 컴퓨터 폴더
파일을 고치면그대로. 다시 docker build해야 함바로 반영됨
쓰임완성한 환경을 전달할 때만들면서 바로 확인할 때

검증은 호스트에서 파일을 고친 뒤 cat으로 내용을 보고, 브라우저를 새로고침해 전후를 비교한다.

볼륨

컨테이너 안에 저장한 파일은 컨테이너를 지우면 사라진다. 남겨야 할 데이터는 볼륨에 둔다.

docker volume create mydata                          # 볼륨 만들기
docker run -it --name test1 -v mydata:/data ubuntu bash   # /data에 연결
docker rm test1                                      # 컨테이너 삭제
docker run -it --name test2 -v mydata:/data ubuntu bash   # 같은 볼륨 연결

test2의 /data에 파일이 남아 있으면 영속성이 확인된 것이다.

저장 위치컨테이너를 지우면쓰임
컨테이너 안사라짐잠깐 쓰는 파일
볼륨 -v 이름:경로남음남겨야 할 데이터
바인드 마운트 -v /폴더:경로남음 (내 폴더에 있음)바로 고쳐 보는 파일
심화: 언제 무엇을 쓰나
  • -v 뒤가 /로 시작하면 바인드 마운트, 이름이면 볼륨이다.
  • DB는 볼륨에 데이터를 두면, 새 이미지로 컨테이너를 만든 뒤 같은 볼륨을 연결해 데이터를 이어 쓸 수 있다.

Git과 GitHub

GitGitHub
역할변경 기록을 남기는 버전 관리 도구저장소를 올려 함께 작업하는 서비스
위치내 컴퓨터 (.git)인터넷 서버
인터넷없어도 커밋할 수 있다푸시, 풀에 필요하다

파일 수정git addgit commitgit pushGitHub 확인

git status                        # 지금 상태 보기
git add README.md                 # 다음 커밋에 넣을 파일 고르기
git commit -m "무엇을 바꿨는지"     # 로컬에 기록
git push                          # GitHub로 올리기
git log                           # 커밋 기록 보기
git status의 표시뜻
Untracked filesGit이 아직 기록한 적 없는 새 파일
Changes not staged for commit수정됐지만 커밋에 고르지 않음
Changes to be committed다음 커밋에 들어감
ahead of 'origin/main'올리지 않은 커밋이 있음

푸시는 커밋을 공유할 뿐 아무것도 실행하지 않는다. 팀원은 pull로 받아 직접 빌드하고 실행한다.

심화: 연결과 설정
명령하는 일
git clone 주소저장소를 기록까지 복제한다
git remote -vorigin의 주소를 본다
ssh -T git@github.comSSH 키 연결을 확인한다
git config 항목실제로 쓰이는 값 하나를 본다
git config --show-origin 항목그 값이 어느 파일에서 왔는지 본다
  • 설정은 system, global, local 순서로 범위가 좁아지고, 겹치면 좁은 쪽 값이 쓰인다.
  • --global 없이 설정하면 그 저장소의 .git/config에만 저장된다.
  • origin/main은 GitHub의 main 위치를 내 컴퓨터가 기억해 둔 것이다.
  • 커밋의 이메일은 공개된다. 공개 저장소는 GitHub의 noreply 주소를 쓸 수 있다.
  • 비밀키, 토큰, 비밀번호는 커밋하지 않는다. 한 번 올라간 기록은 설정을 바꿔도 남는다.
